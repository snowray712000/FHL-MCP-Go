# 使徒教父著作：信望愛 API 整合指南

給另一個專案做設計、規畫、實作時參考。內容取自本專案（FHL-MCP-Go 1.2.1）的程式與測試，不是從 README 推測。
來源檔案：`internal/fhlapi/client.go`、`internal/bible/scripture.go`、`internal/bible/scripture_books.json`、
`internal/tools/tools_scripture.go`、`internal/tools/m2g_test.go`、`tests/fixtures/`、`tests/oracle/scripture_oracle.py`、
`doc/m0/tool-matrix.md`（D24）。

標示「未驗證」的是本專案沒有實測過的部分，請在新專案自行確認。

## 1. 一句話摘要

使徒教父著作（黃錫木主編《使徒教父著作》，上游版本代碼 `afhuang`）由信望愛 Bible API 的兩支 PHP 端點提供：
`qaf.php` 查經文，`seaf.php` 搜關鍵字。書卷清單沒有上游端點，要自己維護一張 17 本的靜態表（編號 201–217）。
次經（`qsub.php` / `sesub.php`，編號 101–115）是同一套寫法，本專案用同一個引擎處理兩者。

## 2. 上游 API

基底網址：`https://bible.fhl.net/api/`，全部 HTTP GET，回 JSON（`Accept: application/json`）。本專案送 `User-Agent: FHL-MCP-Go`，逾時 30 秒，回應最多讀 8 MiB。

### 2.1 `qaf.php`：查經文

| 參數 | 說明 |
| --- | --- |
| `bid` | 書卷編號 201–217（見 §4） |
| `chap` | 章 |
| `strong` | 固定送 `0` |
| `sec` | 節，可省略；省略 = 整章。格式 `1`、`1-5`、`1,3,5`、`1-2,5,8-10` |

實際請求例：`qaf.php?bid=212&chap=1&strong=0&sec=1-2`

回應（資料來自 `tests/fixtures/upstream/qaf_did_1_1-2.json`，中文是 `\uXXXX` 跳脫）：

```json
{
"status":"success",
"record_count":2,
"v_name":"黃錫木主編《使徒教父著作》",
"version":"afhuang",
"proc":0,
"record":[{"engs":"Did.","bid":212,"chineses":"十二使徒遺訓","chap":1,"sec":1,"bible_text":"道路有兩條：…"},
          {"engs":"Did.","bid":212,"chineses":"十二使徒遺訓","chap":1,"sec":2,"bible_text":"生命之路是這樣的：…【1】…"}],
"prev":{"chineses":"十二使徒遺訓","bid":212,"engs":"Did.","chap":0,"sec":0},
"next":{"chineses":"十二使徒遺訓","bid":212,"engs":"Did.","chap":1,"sec":3}
}
```

重點：
- 數字欄位（`bid`、`chap`、`sec`、`record_count`）上游有時是數字、有時是字串，本專案用 `json.RawMessage` 原樣保留（見 §5.4）。
- `prev` / `next`、`proc`、`engs`、`chineses` 在經文工具中沒有用到（`chineses` 只在搜尋結果當書名備援）。
- 章節不存在時仍回 `status:"success"`，`record_count:0`、`record:[]`（fixture `qaf_1clem_99.json`）。這不是錯誤。

### 2.2 `seaf.php`：關鍵字搜尋

| 參數 | 說明 |
| --- | --- |
| `q` | 關鍵字（本專案一律先轉成繁體，見 §3） |
| `offset` | 跳過筆數 |
| `limit` | 回傳筆數；上游把 `0` 視為不限 |

請求例：`seaf.php?limit=3&offset=0&q=%E6%95%99%E6%9C%83`（參數依字母排序，是 Go `url.Values.Encode()` 的結果）。

回應：`{"status":"success","orig":"0","key":"教會","record_count":3,"record":[{engs,bid,chineses,chap,sec,bible_text}, ...]}`

重點：
- **`chap:0`、`sec:0` 的命中是「書卷導論」**，不是經文。`bible_text` 是整篇導論（可達數千字），內含 `<br/>`、`<h2>…</h2>` 等 HTML。fixture `seaf_church_limit3.json` 的 3 筆命中，有 2 筆是導論（帕皮亞殘篇、黑馬牧人書），單筆約 5–6 KB。新專案若要餵給 LLM，要決定是否截斷、轉純文字，或分開標示。本專案**原樣輸出，沒有轉換**。
- `record_count` 在有 `limit` 時是「本頁筆數」，不是總命中數。要知道總數得自己翻頁（本專案的 `total_count` 照原版輸出此值，即 D20，名稱有誤導性）。
- `limit` 太大是否受上游 500 筆上限影響：`se.php`（新舊約搜尋）確定有 500 上限（本專案為它做了分頁合併），`seaf.php` **未驗證**。

### 2.3 錯誤與怪癖（皆為實測）

| 情況 | 上游行為 | 本專案處理 |
| --- | --- | --- |
| `q` 為空 | `status:"Fail: Empty Query"` | 呼叫前就擋掉：`Invalid parameter 'query': must not be empty`，不打上游 |
| `sec` 格式不合 | `status` 內夾帶上游 SQL 片段（會洩漏內部資訊） | 呼叫前以 regexp `^[0-9]+(-[0-9]+)?(,[0-9]+(-[0-9]+)?)*$` 擋掉 |
| 章節不存在 | 成功、0 筆 | 回 `verse_count:0`、`book_id:"未知"`、`verses:[]` |
| `status != "success"` | 其他失敗字串 | 一律轉成 `ErrUpstream`（訊息含 status） |
| HTTP ≥ 400 | — | `ErrHTTP`；連線失敗 `ErrNetwork`；JSON 解析失敗 `ErrParse` |

## 3. 轉換與清理（從上游到輸出）

1. **書名 → 編號**：工具收到的 `book` 可以是中文簡稱、全名、英文縮寫、英文名或數字，由本地表解析成 `bid`，上游只收數字（§4）。
2. **簡體書名**：解析失敗時，把簡體字逐字轉成繁體（`foldSimplifiedBook`，用 `s2tBookChars` 字表）再查一次，所以 `黑马牧人书` 可用。
3. **搜尋關鍵字一律轉繁體**：`hanzi.ToTraditional(keyword)` 才送出。原因：上游經文是繁體，簡體關鍵字會找不到。注意 `seaf` / `sesub` 沒有 `gb` 參數，所以不論全域是否預設簡體，這兩支搜尋都固定用繁體。
4. **回傳文字不轉簡體**：這 6 個工具沒有 `use_simplified` 參數，`bible_text` 原樣輸出（繁體）。
5. **JSON 數字/字串保留**：`bid`、`chap`、`sec`、`record_count` 用 `json.RawMessage` 讀，再用 `norm()` 重新編碼（去掉 `\uXXXX` 跳脫、保留 number 或 string 的原形、不跳脫 HTML 字元）。新專案若用強型別，要小心上游同一欄位型別不固定。
6. **`book` 欄位以本地表為準**：經文結果的 `book` 一律是解析後那本書的中文名；搜尋結果依命中的 `bid` 查表，查不到才用上游 `chineses`，`bid` 為空/0 時 `book` 為空字串。
7. **預設值**：上游沒給版本時，`version` 補 `{code:"af", name:"黃錫木主編《使徒教父著作》"}`（上游實際一律給 `afhuang`）。
8. **經文內嵌註腳標記 `【1】`、`【2】` 不處理**，原樣保留在 `text`。這批註腳的內容本專案沒有對應端點可取（`get_bible_footnote` 只支援聖經譯本）。
9. **輸出格式**：縮排 2 空格的 JSON 字串，不跳脫 HTML、中文不轉 `\u`。在 MCP 層同時送 text content 與 `structuredContent:{"result":"<同一字串>"}`。

解析規則（`ScriptureSet.resolve`）：
- 純數字：必須在 201–217，否則報錯。
- 其他：精確比對別名；英文（純 ASCII）不分大小寫，中文要完全相同。
- 找不到：先把簡體字轉繁體再比一次。
- 仍找不到：回 `Invalid parameter 'book': <輸入> - Not a book of this collection (201-217). Use the matching list_*_books tool to see the valid names and ids.`

注意事項：
- **`伊` 刻意不收**：它可能是 7 封伊格那丟書信的任何一封，歧義就報錯，不猜。
- `坡`、`Pol`、`Polycarp` 指向 210（致腓立比人書）是我們的假設，不是上游規定。
- `巴` 在使徒教父是 213（巴拿巴），在次經是 109（巴錄書），兩個集合各自一張表，不能共用別名表。
- 「衆」用的是上游的異體字 `衆`（不是 `眾`），217 的名稱要照抄。
- 中文全名部分是我們依上游 `chineses` / `engs` 整理的，未經官方確認；同一表也供 `list_apostolic_fathers_books` 輸出。
- 章節數沒有內建表。想做「不存在的章」的預檢，需要自己實測各書章數；本專案沒有做，直接問上游。伊格那丟書信等單章書的實際章節編號是否從 1 起：**未驗證**。

### 4.1 D24：為什麼不能沿用 Python 原版的編號

Python 參考實作（`FHL-MCP-Server`）的書卷編號和上游實際編號不一致：它送 `bid=101` 查「多俾亞傳」，上游回的是瑪加伯上，再用自己的表標成多俾亞傳，結果書名與內容不符。本專案改用上游編號（以 `bid` → 回傳 `engs` / `chineses` 實測取得）。新專案請**不要**照抄 Python 的表，也不要只信 README。上游官方文件在 `https://bible.fhl.net/json/`。

## 5. 對外工具介面（若新專案也提供 MCP 工具）

| 工具 | 參數 | 預設 |
| --- | --- | --- |
| `get_apostolic_fathers_verse` | `book` (必填 string)、`chapter` (必填 integer)、`verse` (選填 string) | `verse` 省略或 null = 整章 |
| `search_apostolic_fathers` | `query` (必填)、`limit` (integer)、`offset` (integer) | `limit` 10、`offset` 0 |
| `list_apostolic_fathers_books` | 無 | — |

參數寬鬆規則（沿用 Python 原版行為，D5/D6）：`chapter`、`limit`、`offset` 可傳數字字串（`"1"`）；值為 `null` 視同沒給。

### 5.1 `get_apostolic_fathers_verse` 輸出（欄位順序固定）

```json
{
  "status": "success",
  "query_type": "apostolic_fathers_verse",
  "book": "十二使徒遺訓",
  "book_id": 212,
  "chapter": 1,
  "verse": "1-2",
  "version": {"code": "afhuang", "name": "黃錫木主編《使徒教父著作》"},
  "verse_count": 2,
  "verses": [{"book": "十二使徒遺訓", "book_id": 212, "chapter": 1, "verse": 1, "text": "…"}]
}
```

- `verse` 是請求時的原字串（含範圍寫法，輸出不去空白），沒給時是 `null`；送給上游的 `sec` 則會先去掉前後空白。
- 找不到內容時：`book_id:"未知"`、`verse_count:0`、`verses:[]`。
- 每筆 `verse` 的數字型別沿用上游（數字或字串）。

### 5.2 `search_apostolic_fathers` 輸出

`status`、`query_type:"apostolic_fathers_search"`、`keyword`（原輸入，未轉繁體）、`total_count`（= 上游 `record_count`，見 §2.2）、`returned_count`、`offset`、`results[]`（`book`、`book_id`、`chapter`、`verse`、`text`）。

### 5.3 `list_apostolic_fathers_books` 輸出

`status`、`query_type:"list_apostolic_fathers_books"`、`id_range:"201-217"`、`book_count:17`、`books[]`（`id`、`name_zh`、`name_en`、`abbreviations`）。純靜態資料，不打上游。

### 5.4 錯誤格式（D2）

工具錯誤回 MCP 結果 `isError:true`，文字前綴 `Error executing tool <工具名>: `，不帶 `structuredContent`。參數驗證訊息為自訂簡短英文（例：`Invalid parameter 'chapter': required parameter is missing`）。

## 6. 快取與請求量

- `qaf.php` 快取 7 天、`seaf.php` 快取 1 天（TTL 為本專案假設，Python 原版只快取經文 7 天、搜尋 1 天）。快取 key 含伺服器、端點與全部參數；只快取 `status == "success"` 的回應。
- 同樣的請求同時進來會合併成一次上游呼叫。
- 這兩支端點沒有發現速率限制，但 `get_apostolic_fathers_verse` 一次只打一個請求；本專案的 `get_parsing_reference` 另有 30 節上限（與使徒教父無關）。

## 7. 設計建議（給新專案）

1. 分三層：**書卷表 + 解析**（純資料，不依賴任何 SDK）→ **上游 client**（可注入、可 mock）→ **工具/介面層**。本專案的 `ScriptureSet` 讓次經與使徒教父共用同一份引擎，只差端點函式、編號範圍、預設版本與 `query_type` 前綴。
2. **先驗證參數再打上游**：空 `query`、不合法 `verse` 都會讓上游回怪訊息（甚至洩漏 SQL），要在本地擋。
3. **導論資料要決定處理方式**：搜尋會命中 `chap:0 sec:0` 的整篇導論（含 HTML）。建議在新專案決定：標示為導論、轉純文字、截斷，或提供「排除導論」選項。本專案原樣輸出，這是已知的 token 風險。
4. **簡繁處理要分開想**：書名簡轉繁（解析用）、關鍵字轉繁（送上游前）、輸出不轉簡（本專案目前行為）三件事互相獨立。
5. **版權**：《使徒教父著作》是黃錫木主編的出版品，由信望愛提供。本專案沒有查證其再散布條件；若新專案要快取到本機、整包下載或重新發布，請先向信望愛確認。
6. 不要信 Python 原版的書卷編號（D24），也不要假設上游數字欄位型別固定。
