## How
Launcher `run_py_server.py` (scratchpad; 127.0.0.1:18081, fhl_bible_mcp DEBUG + httpx INFO to a log file); `sample_runner.py` called tools
sequentially via the mcp client, slicing the server log per call to record upstream URLs; >=1.5 s gap after any call that hit upstream.
Two batches (26 + 29 calls). Total 32 real upstream requests. Cache dir was cwd-relative -> scratchpad, so the Python repo `.cache` is untouched
(latest mtime 07:32, before this session; `git status` still 15 lines). Server killed by port afterwards.
Output shapes/endpoint map generated by script (`merge.py`), not hand-copied.

## Key findings
- Upstream is ALWAYS `https://bible.fhl.net/api/*.php` (ab, au, qaf, qb, qp, qsub, rt, sc, sd, se, seaf, sesub, ssc, st) + `https://www.fhl.net/api/json.php` for articles; no `/json/` request seen.
- 6 tools are fully static (no upstream): get_book_list, get_book_info, list_audio_versions, list_apocrypha_books, list_apostolic_fathers_books, list_fhl_article_columns.
- `use_simplified` is silently ignored by most tools (no `gb=1`), cache key excludes it; only footnote and articles honored it.
- Unknown-book InvalidParameterError ctor bug is in get_book_info AND get_audio_chapter_with_text (not only get_book_info).
- Errors (incl. unknown tool, Pydantic validation) are `isError:true` results, not JSON-RPC errors; null for `verse` is rejected though default is null.
- Empty search query leaks `KeyError('record')`; `search_commentary("愛")` returns 0 (unexplained).
